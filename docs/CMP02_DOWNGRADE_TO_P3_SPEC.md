## 3. 降级影响评估

### 3.1 对门禁体系：无影响

`theme:hardcode-baseline` 双 lane（modules blue+indigo 全 0/0；semantic sops 4087 只降不升 + per-file 双锁）继续在线拦截新增未管控硬编码。TD-CMP-02 的优先级标签本身不进入任何门禁，降级不会改变 gate 行为。TD-THM-02 已完成同样降级（P1→P3，`44739732`），门禁依旧在线，可作为先例。

### 3.2 对发布流程：无影响

无未完结的表单债 blocker。rc.4 及后续版本可照常发布；手动发布动作（GitHub Actions 月度限额问题）不受降级影响。

### 3.3 对遗留机制：需要维持的两件事

降级不等于遗忘，两项机制需在 P3 状态下继续维持。其一是 **semantic lane baseline 双锁**：slate 结构性灰调 180 处仍在 baseline 4087 内，gate 会继续拦截任何增量，这是「只降不升」的长期防线；其二是 **forms 9.1 空壳保留项**：forms.css 补丁机制仍在为 <768px 焦点环提供兜底，按 4A 登记保留，任何对 forms.css 的大改动（如 workbench migration）时需复查一次。

### 3.4 对路线图：次序 13 成为下一个高价值项

看板与路线文档剩余项已于 `1e34a523` 更新为次序 13。TD-CMP-02 降 P3 后，技术债治理的主线聚焦顺序为：次序 13（slate 结构性灰调统一化）→ 自动化发布流水线回归（GitHub Actions 月度限额恢复）→ TD-THM-01 20 处 intentional override 的 workbench migration 统一时机。
