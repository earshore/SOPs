# v3.0.7-rc.1 发布与生产部署设计

## 目标

将 `v3.0.6` 之后的已提交变更发布为 `v3.0.7-rc.1`，创建 GitHub Pre-release 及可校验的构建资产，并将同一构建覆盖部署到 Cloudflare Pages 生产分支。

## 发布语义

- Git tag、`package.json`、`package-lock.json` 和应用构建版本统一为 `3.0.7-rc.1`。
- GitHub Release 标记为 Pre-release，不标记为 Latest。
- GitHub Latest 保持稳定 GA `v3.0.6`。
- Cloudflare Pages 项目仍为 `sops`，生产分支为 `main`，正式域名为 `https://sops.hongecb.store`。
- 生产域允许运行 RC；上一条 `v3.0.6` Pages 部署保留为回滚点。

## 发布内容

本次 RC 包含 `v3.0.6` 之后的三个提交方向：

1. GitHub 历史 Release 去重与 tag-only 归档策略。
2. Keyword Hunter 图例、PromptLab 交接与去重优化。
3. 关闭 Keyword Hunter 流程快照的自动恢复，避免旧快照干扰新流程。

CHANGELOG 将把当前 `Unreleased` 内容迁入 `3.0.7-rc.1`，并补齐上述功能变更。README 继续明确 `v3.0.6` 是稳定 Latest，同时标注 `v3.0.7-rc.1` 为当前生产候选版本。发布策略的下一候选号更新为 `3.0.7-rc.2`。

当前未提交的 `docs/XSS_SCAN_REPORT.md` 仅包含扫描时间戳变化，不进入发布提交。构建产生的新时间戳同样在提交前恢复，避免生成噪声污染版本历史。

## 发布流程

1. 更新版本文件、CHANGELOG、README 和发布策略。
2. 运行 `release:validate`、完整 `npm run build`、全量 Vitest 和 Chromium 发布冒烟测试。
3. 创建发布提交并推送 `main`。
4. 重新生成带发布 commit SHA 的 notes、zip、`build-info.json` 和 `SHA256SUMS.txt`。
5. 创建并推送 annotated tag `v3.0.7-rc.1`，由 Release workflow 创建 GitHub Pre-release 并上传正式资产。
6. 使用同一 `dist` 执行 `wrangler pages deploy dist --project-name sops --branch main`，覆盖生产环境。

## 验证与错误处理

- 任一安全、质量、测试、构建或版本校验失败时停止，不创建 tag、不部署。
- GitHub Release workflow 必须成功，Release 必须是非草稿 Pre-release，且 Latest 仍返回 `v3.0.6`。
- Release 资产必须包含 `sops-dist-3.0.7-rc.1.zip`、`build-info.json` 和 `SHA256SUMS.txt`，其中 commit SHA 与 tag 指向一致。
- Cloudflare 部署记录必须对应发布 commit；正式域和部署 URL 均返回 HTTP 200，CSP 保留所需网关域名。
- 部署验证失败时停止后续声明，并使用 Cloudflare 上一条 `v3.0.6` 生产部署作为回滚目标。

## 完成标准

- `main`、`v3.0.7-rc.1` tag、GitHub Pre-release 和 Cloudflare 生产部署指向同一发布 commit。
- GitHub Latest 保持 `v3.0.6`。
- 全部发布门禁通过，工作区除发布前已有的 XSS 时间戳噪声外无未提交变更；最终该时间戳噪声也恢复到原状态。
