# 架构债务消除代理团队使用指南

**最后更新**: 2026-04-17

## 团队成员

### 1. 架构债务项目经理 (arch-debt-pm)
**职责**: 整体规划、进度跟踪、风险管理

**何时使用**:
- 需要制定整体修复计划时
- 需要评估剩余债务时
- 需要生成进度报告时

**调用方式**:
```
@arch-debt-pm 请扫描项目并制定第一批修复计划
```

### 2. 重构工程师 (refactor-engineer)
**职责**: 执行具体的代码修复工作

**何时使用**:
- 需要执行具体修复时
- 需要批量处理相似问题时

**调用方式**:
```
@refactor-engineer 请修复以下文件的错误处理：
- src/modules/xxx/xxx.ts
- src/modules/xxx/xxx.ts
```

### 3. 代码架构审计师 (code-auditor)
**职责**: 代码审查、质量把关

**何时使用**:
- 修复完成后需要审查时
- 需要验证架构一致性时

**调用方式**:
```
@code-auditor 请审查第1批修复的代码质量
```

## 标准工作流程

### 阶段1: 规划阶段
```
用户: @arch-debt-pm 请扫描项目并制定修复计划

项目经理:
1. 扫描项目，统计架构债务
2. 生成债务清单
3. 制定分批修复计划
4. 输出计划文档
```

### 阶段2: 审查计划
```
用户: @code-auditor 请审查修复计划

审计师:
1. 评估计划合理性
2. 识别风险点
3. 提出优化建议
4. 批准或要求调整
```

### 阶段3: 执行修复
```
用户: @refactor-engineer 请执行第1批修复

工程师:
1. 读取需要修复的文件
2. 执行代码修复
3. 运行构建验证
4. 生成修复报告
```

### 阶段4: 审查修复
```
用户: @code-auditor 请审查第1批修复

审计师:
1. 检查代码质量
2. 验证架构一致性
3. 运行构建验证
4. 批准或要求改进
```

### 阶段5: 进度更新
```
用户: @arch-debt-pm 请更新进度并规划下一批

项目经理:
1. 更新进度文档
2. 记录经验教训
3. 规划下一批修复
4. 生成进度报告
```

## 快速开始示例

### 示例1: 完整流程
```bash
# 步骤1: 制定计划
@arch-debt-pm 请扫描项目，统计剩余的架构债务，并制定第一批修复计划

# 步骤2: 审查计划
@code-auditor 请审查项目经理制定的修复计划

# 步骤3: 执行修复
@refactor-engineer 请执行第1批修复任务

# 步骤4: 审查修复
@code-auditor 请审查第1批修复的代码质量

# 步骤5: 更新进度
@arch-debt-pm 请更新进度并规划第2批修复
```

### 示例2: 针对特定类型的债务
```bash
# 只修复错误处理
@arch-debt-pm 请制定一个专门修复错误处理的计划

# 只修复存储访问
@arch-debt-pm 请制定一个专门修复localStorage直接访问的计划
```

### 示例3: 紧急修复
```bash
# 跳过规划，直接修复指定文件
@refactor-engineer 请修复以下文件的错误处理：
- src/modules/app_center/xxx.ts
- src/modules/app_center/yyy.ts

# 然后审查
@code-auditor 请审查刚才的修复
```

## 常见问题

### Q: 如何选择第一批修复的文件？
A: 让项目经理扫描并制定计划，它会根据优先级和风险评估选择合适的文件。

### Q: 修复失败怎么办？
A: 工程师会报告失败原因，审计师会提供改进建议，必要时可以人工介入。

### Q: 如何确保修复质量？
A: 每批修复都会经过审计师审查，并运行构建验证，确保没有引入新问题。

### Q: 可以跳过某个代理吗？
A: 可以，但不建议。完整流程能确保修复质量和架构一致性。
