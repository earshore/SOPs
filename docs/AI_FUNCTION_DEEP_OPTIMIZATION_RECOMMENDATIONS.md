# AI 功能深度优化建议清单

## 评估范围与假设

- 本项目当前没有本地训练或微调模型代码，AI 能力主要通过 OpenAI-compatible LLM 网关完成。
- 已集成 AI 功能集中在：
  - `master_analysis/ai_analysis`：竞品数据的 8 维 AI 分析，包含并行调度、缓存、流式结果与 JSON 解析。
  - `playground/deep-chat`：通用 Deep Chat，对话历史、系统提示词、流式输出与停止生成。
  - `ppc_tools/ppc_search_terms`：PPC 搜索词 Agent，先用本地规则全量预判，再用 LLM 复核低置信候选。
  - `promptlab` / `keyword_hunter`：消费 AI 分析报告或触发 LLM 语义分析的下游工作流。
- 因此，本轮“模型优化”重点不是调整本地神经网络结构，而是优化模型调用策略、上下文构造、数据质量、输出约束、缓存与推理体验。

## 本轮已实施优化

1. Deep Chat 默认请求预算改为动态模型感知：
   - 根据当前模型 `context` 推导输入窗口，优先保留最新用户输入和系统提示词。
   - 普通 5-6k token 长 Prompt 不再因固定 24,000 字符线被误拦截。
   - 历史会话超出预算时自动裁剪旧上下文，只有单条输入明显超过目标模型能力时才提示缩短。
   - 预期兼顾质量、首 token 速度和成本控制。

2. LLM 取消信号可靠性修复：
   - 如果外部 `AbortSignal` 在调用前已取消，现在会立即传递到内部请求 controller。
   - 流式响应刷新超时时，不再误移除外部取消监听。
   - 预期改善 Deep Chat “停止生成”和页面切换后的请求中断体验。

## 优先级建议

| 优先级 | 问题描述 | 优化方案 | 预期效果 | 资源估算 |
| --- | --- | --- | --- | --- |
| P0 | Deep Chat 既要支持 5-6k token 的长 Prompt，又不能把全部历史无脑塞进模型，固定字符阈值容易误伤正常输入。 | 已改为模型感知的动态预算：按当前模型 context 计算输入窗口，保留最新输入，自动裁剪旧历史，仅对明显超出目标模型能力的单条输入提示缩短。 | 长 Prompt 可正常发送，首 token 和成本更稳定，历史会话不会无限膨胀。 | 已完成；UI 微调 0.5-1 人日。 |
| P0 | 用户停止生成、切换页面或删除会话时，已取消信号可能没有及时传入底层请求。 | 已修复 LLM abort 资源管理；补充前置 abort 测试。 | 停止生成更确定，减少后台悬挂请求和重复计费风险。 | 已完成。 |
| P0 | AI 分析仍依赖单次模型输出质量，缺少可量化的离线评测集，团队很难判断 Prompt、模型或采样改动是否真的变好。 | 建立 20-50 个真实商品样本的 golden set，记录 schema 通过率、证据支持率、幻觉率、完整度、TTFT、总耗时、缓存命中率。把评测接入 `vitest` 或独立评测脚本。 | 后续优化可被量化，避免凭主观感受改 Prompt；降低回归风险。 | 5-8 人日；需要运营/业务 SME 标注样本。 |
| P1 | 8 个 AI 分析维度共用相近输入策略，评论样本虽已截断，但不同任务仍可能消费不必要上下文。 | 建立任务级 evidence pack：低星任务只取低星证据，高星任务只取高星证据，通用任务使用代表性混合样本；给评论分配 evidence id，让模型返回 evidence id 而非长引文。 | 输入 token 下降约 20%-40%，输出更可追溯，报告可信度更高。 | 3-5 人日；需要补 parser 与报告渲染适配。 |
| P1 | 当前模型选择主要来自用户配置，同一模型处理所有任务，速度/成本/质量无法按任务分层。 | 在网关支持的前提下做模型路由：标题/卖点等低风险任务走快模型，致命缺陷/承诺落差等高风险任务走强模型；保留用户手动覆盖。 | 平均耗时与成本下降，同时把高推理能力留给高价值任务。 | 3-5 人日；依赖网关模型列表和小型评测集。 |
| P1 | 并发计划在任务启动前决定，运行中遇到 429、超时、长 TTFT 时缺少自适应降级。 | 在 `parallelAnalysisService` 记录 429/timeout/firstResponseMs，运行时降低后续并发和重试预算；把降级原因显示在进度状态中。 | 限流场景下成功率提升，用户能理解为什么速度变慢。 | 3-5 人日。 |
| P1 | PPC Agent 已采用“本地规则 + LLM 复核”，但低置信候选阈值缺少持续校准。 | 对 PPC 决策建立人工复核样本，按 false positive / false negative 调整 `selectPpcAgentModelRows` 阈值；记录被 LLM 覆盖的规则类型。 | 减少无效 LLM 行数，避免漏掉高风险搜索词。 | 4-6 人日；需要广告运营样本。 |
| P2 | JSON 模式仍依赖模型自觉遵守 schema，失败后靠 `jsonrepair` 修复，复杂输出时仍会有解析和字段缺失风险。 | 若网关支持 constrained decoding / JSON schema，按任务 schema 发送结构化约束；否则继续保留 zod 校验与 repair fallback。 | schema mismatch 降低，报告字段稳定性提升。 | 2-4 人日；依赖网关能力。 |
| P2 | 缓存已覆盖 AI Analysis 与 PPC 批次，但缺少统一可观测指标，例如命中率、节省时长、缓存失效原因。 | 给 AI Analysis、PPC LLM cache 增加轻量指标：hit/miss/stale、命中节省耗时、按 provider/model 统计；只在本地展示，不上传敏感数据。 | 用户更清楚“为什么这次快/慢”，团队能定位缓存收益。 | 2-3 人日。 |
| P2 | PromptLab 下游依赖 AI 分析报告置信度，但用户仍可能把低置信字段直接用于最终 Prompt。 | 在 PromptLab 生成前加入低置信字段提示和可选排除；生成 Prompt 时标注来源字段置信度。 | 降低错误洞察进入 Listing/视觉 Prompt 的概率。 | 2-4 人日。 |

## 推荐执行顺序

1. 先补 AI 评测集和指标，否则后续 Prompt、模型路由、采样策略难以判断收益。
2. 同步推进 evidence pack 与模型路由，这是当前最接近“模型架构优化”的落地点。
3. 再做运行时自适应并发和缓存可观测，让用户体验从“能跑完”提升到“可解释、可预测”。
