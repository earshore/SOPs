使用 OpenClaw 前必读 · 两条关键须知

独立页把“模型能力差异”和“不要复制粘贴提示词”放在最前面。它提醒用户：OpenClaw 是大模型与工具链的调度器，效果取决于模型能力、任务拆解方式、工具调用稳定性和每一步是否经过人工验证。

本页正文按该独立页复刻为普通说明页，作为后续四个业务场景的前置安全说明。

参考页面

先看模型档位

任务拆解、工具调用、分类归因、长上下文和多语种话术，都会受底层大模型能力影响。

先当试跑样例

示例中的店铺、订单、看板数字和对话均为演示数据，用于说明节奏和验收方式。

一步一验收

每一步只做一件事，先看产物和数量，再进入下一步；不要把整段流程一次性丢给 OpenClaw。

关键动作留人工

公开回复、广告改价、暂停广告组、合规确认等高风险动作，先生成建议，确认后再执行。

Core Notice

两条关键须知

来源页面

不同模型会跑出不同质量

OpenClaw 本质上是在调度大模型与工具链。底层模型不同，同一套 SOP 在任务规划、等待页面渲染、识别 DOM、生成话术、保留多轮约束上都会出现差距。

计划能力

能否把大任务拆成可验证小步，并主动停下来等待确认。

工具稳定性

是否按正确顺序调用浏览器、采集、去重、渲染和推送工具。

语义判断

能否区分产品质量、期望偏差、详情页误导、无关搜索词等细分类别。

长上下文

能否记住会话中被修改过的规则，并写进最终 SOP。

这不是复制粘贴提示词

示例对话的价值在于演示如何“教”OpenClaw，而不是提供一段万能指令。直接复制长段需求，常见结果是漏等 SPA、漏抓入口、分类口径跑偏或高风险动作过早自动化。

  1. 1
    分步引导

    先让它列计划，再从第一步开始跑。

  2. 2
    跑通验证

    确认数量、字段、分类、话术和报告格式。

  3. 3
    沉淀工作流

    把已经确认过的步骤、参数和异常兜底写进 SOP。

  4. 4
    再挂定时

    定时任务只绑定已验证 SOP，并明确推送、@ 人和失败重试规则。

Before Run

启动前检查清单

环境与凭证

  • 紫鸟浏览器客户端支持 OpenClaw 桥接
  • 店铺登录态有效，二次验证已处理
  • 紫鸟助理 API Key 已配置

任务边界

  • 先定义店铺、市场、时区和数据窗口
  • 高风险动作只生成草稿或手册
  • 每步要有可核对的数量或样本

沉淀标准

  • 会话中改过的规则写进 SOP
  • 失败重试、缺失数据、告警方式明确
  • 换模型或 UI 改版后重新回归
