## 🔧 涉及的文件

### 需要修改的文件（新增网关时）

1. `src/common/constants/constants.ts` - 前端配置
2. `functions/v1/chat/completions.js` - 对话 API 路由
3. `functions/v1/models.js` - 模型列表 API 路由
4. `src/common/config/apiEndpoints.ts` - 端点白名单
5. `.env` - 本地环境变量
6. Cloudflare Pages 环境变量 - 生产配置

### 配置层级

```
前端配置 (constants.ts)
    ↓
路由配置 (completions.js, models.js)
    ↓
安全配置 (apiEndpoints.ts)
    ↓
环境变量 (.env, CF Pages)
```

## 📚 关键操作流程

### 新增网关（6 步）

1. **注册前端配置** - 添加到 `PROVIDERS` 对象
2. **注册 CF 路由** - 更新 `resolveGateway()` 函数
3. **更新端点白名单** - 添加到 `API_ENDPOINTS`
4. **配置本地环境** - 更新 `.env` 文件
5. **同步生产环境** - 使用 `wrangler pages secret bulk`
6. **重新部署** - 构建并部署到 CF Pages

### 更新 API Key（3 步）

1. 更新 `.env` 中的 `GATEWAY_*_API_KEY`
2. 更新 CF Pages 环境变量
3. 无需重新部署（立即生效）

### 删除网关（5 步）

1. 移除前端配置
2. 移除路由配置
3. 移除端点配置
4. 清理环境变量
5. 重新部署

---

## 🛠️ 故障排查要点

### 常见问题

1. **CORS 错误** → 检查 `normalizeEndpoint()` 返回相对路径
2. **401 错误** → 验证 `AUTH_PASSWORD` 匹配
3. **API Key 未配置** → 检查 CF Pages 环境变量
4. **未知网关** → 确保三处配置同步
5. **模型列表 vs 对话不一致** → 同步 `models.js` 和 `completions.js`
6. **生产拦截** → 确认 `isDangerous: false`

## ✅ 最佳实践

### 命名规范

- **provider_id**: 小写字母 + 下划线（如 `new_api`）
- **环境变量**: `GATEWAY_{ID}_BASE_URL` / `GATEWAY_{ID}_API_KEY`
- **显示名称**: 用户友好（如 "NEW API"）

### 安全实践

- 永远不提交 API Key 到 Git
- 使用环境变量管理敏感信息
- 定期轮换 API Key
- 所有请求经 CF Functions 代理

### 测试流程

1. 本地测试 → 配置 `.env` → 测试连接
2. 生产测试 → 部署 CF Pages → 验证环境变量
3. 回归测试 → 确保现有网关正常
