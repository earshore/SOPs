## 问题分析

### 原有架构的问题

1. **translateType 函数（154-172行）**
   - 硬编码 13 种类型翻译（size→尺寸, color→颜色等）
   - 导致新品类的类型无法翻译，输出中英文混杂
   - 每增加新品类需要手动添加翻译

2. **isTechnicalSpec 函数（178-192行）**
   - 硬编码 17 种技术单位（dB, Hz, mAh, GB等）
   - 无法识别新品类的单位（如假发的 density, lace）
   - 限制了系统的扩展性

3. **extractSpecsByType 函数（198-219行）**
   - 依赖 translateType，继承其所有限制
   - 函数本身设计良好，但被翻译逻辑拖累

### 跨品类可用性评估（重构前）

| 品类 | 可用性 | 主要问题 |
|------|--------|---------|
| 香水 | 90% | 类型基本覆盖 |
| 假发 | 60% | 类型翻译失败，输出混乱 |
| 电子产品 | 70% | 部分类型翻译失败 |
| 美妆 | 60% | 类型和单位识别不足 |

## 重构方案

### 设计原则

1. **完全数据驱动**: 不预设任何产品属性，完全基于 AI 报告数据
2. **零硬编码**: 移除所有品类特定的硬编码逻辑
3. **品类无关**: 支持任意产品品类，包括未来的新品类
4. **向后兼容**: 不破坏现有功能

### 核心变更

#### 变更 1: 删除 translateType 函数

**删除代码**:
```typescript
function translateType(type: string): string {
  const translations: Record<string, string> = {
    'size': '尺寸',
    'color': '颜色',
    'material': '材质',
    // ... 13 种硬编码翻译
  };
  return translations[type] || type;
}
```

**理由**:
- AI 报告本身是英文，技术参数也包含英文（如 "50ml", "20 inch"）
- 使用英文 type 标签与参数值风格一致
- 消除维护负担，实现真正的零硬编码

#### 变更 2: 优化 isTechnicalSpec 函数

**之前**:
```typescript
// 硬编码单位列表
const hasTechTerm = /\b(dB|Hz|V|W|mAh|GB|TB|MB|kg|lbs|oz|cm|mm|inch|ml|L|g)\b/i.test(text);
```

**之后**:
```typescript
// 通用模式匹配，6 种模式
const hasNumberWithUnit = /\d+\s*[a-zA-Z]+/.test(text);           // 50ml
const hasUnitWithNumber = /[a-zA-Z]+\s*\d+/.test(text);           // SPF 50
const hasPercentage = /\d+\s*%/.test(text);                       // 150%
const hasRange = /\d+\s*[-~x]\s*\d+/i.test(text);                 // 13x4
const hasDecimal = /\d+\.\d+/.test(text);                         // 6.5
const hasNumberHyphenUnit = /\d+\s*-\s*[a-zA-Z]+/.test(text);     // 24-hour
```

**改进**:
- 移除硬编码单位列表
- 新增 3 种模式（模式 2, 5, 6）
- 覆盖更多技术规格格式

#### 变更 3: 更新 extractSpecsByType 函数

**之前**:
```typescript
grouped.forEach((kws, type) => {
  const label = translateType(type);  // 调用翻译
  specs.push(`${label}: ${kws.join(', ')}`);
});
```

**之后**:
```typescript
grouped.forEach((kws, type) => {
  specs.push(`${type}: ${kws.join(', ')}`);  // 直接使用原始 type
});
```

**改进**:
- 移除翻译依赖
- 代码更简洁
- 完全品类无关
