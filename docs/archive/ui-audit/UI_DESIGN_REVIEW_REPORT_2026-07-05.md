# SOPS 现有 UI 设计全面评审与优化方案

> 评审对象：`sops` 亚马逊运营管理平台前端界面与样式体系  
> 评审日期：2026-07-05  
> 评审角色：UI Designer  
> 评审依据：设计令牌、核心 CSS、首页、应用中心、设置面板、模态框等实现文件抽样审查

## 0. 评审结论摘要

当前 UI 已具备较完整的设计令牌体系、模块化样式结构、较清晰的业务分区，以及部分良好的无障碍实践（如 `aria-live`、`aria-pressed`、`focus-visible`、`prefers-reduced-motion`）。但整体仍存在“设计系统与业务实现脱节”的问题：令牌定义重复、局部页面大量硬编码颜色与 `!important`、组件交互模式不统一、移动端部分导航与内容策略偏弱、暗色模式覆盖不完整。

建议优先把优化重点放在 **设计令牌收敛、移动端关键路径补齐、可访问性交互语义修复、组件状态统一** 四个方向。视觉上的“好看”已经有基础，下一步应该让它更稳定、更一致、更可维护。

## 1. 整体评分（0-4）

| 维度 | 评分 | 关键判断 |
|---|---:|---|
| 视觉层次 | 3.0 | 应用中心、首页 Hero 层次明确，但不同模块的标题、卡片、标签体系不够统一。 |
| 色彩搭配 | 2.5 | 基础色板完整，但业务模块出现较多硬编码品牌色、渐变与局部覆盖，主题一致性受影响。 |
| 排版 | 2.8 | 字体令牌较完整，但默认字号、页面标题、卡片正文、表单标签之间仍有多套规则。 |
| 交互反馈 | 2.7 | Hover、active、focus 有覆盖，但反馈强度、按钮尺寸、嵌套点击区域存在不一致。 |
| 响应式适配 | 2.4 | 有断点，但部分导航直接隐藏、筛选行横向滚动、复杂面板移动端空间压力较大。 |

## 2. 必须改进（P1：对用户体验影响高）

### P1-01 设计令牌存在重复来源与命名分裂

- **位置 / 证据**
  - `src/common/config/design-tokens.ts`
  - `src/css/foundation/variables.generated.css`
  - `src/css/foundation/variables.css`
  - `src/css/critical.css`
- **问题分析**
  - 同时存在 `--color-text-primary`、`--text-primary`、`--bg-primary`、`--color-bg-primary` 等多套语义变量。
  - `critical.css` 又重新定义 `--color-primary`、`--font-sans`、`--gradient-aurora` 等首屏变量。
  - 自动生成变量和手写变量覆盖顺序复杂，组件很容易引用到不同语义层级。
- **用户体验影响**
  - 同类页面视觉气质不稳定，尤其在主题切换、组件复用、后续新增页面时容易出现颜色、间距、阴影不一致。
  - 维护成本上升，后续做暗色模式或品牌升级会变成“到处补丁”。
- **优化方案**
  1. 明确三层令牌：基础色板 `--color-blue-500`、语义令牌 `--color-primary`、组件令牌 `--button-primary-bg`。
  2. 保留 `design-tokens.ts` 作为唯一源头，`variables.generated.css` 只生成基础与语义令牌。
  3. 将 `variables.css` 中手写变量迁移为“组件令牌覆盖层”，禁止重新定义基础色板。
  4. `critical.css` 只引用令牌，不再声明重复主色、字体、渐变。
  5. 建立 CSS 审计规则：新增 `#hex`、裸 `rgba()`、局部 `--color-primary` 覆盖必须说明原因。
- **验收标准**
  - 全局只保留一套文本、背景、边框语义变量。
  - 关键页面在浅色 / 暗色主题下无需局部补丁即可保持可读。

### P1-02 移动端主导航被直接隐藏，缺少等价入口

- **位置 / 证据**
  - `src/css/critical.css:376-383`：`.nav-wrapper { display: none; }`
  - `src/css/components/header.css:688-699`：传统 header 有移动端按钮，但当前关键首屏 header 与 mega menu 体系未明确等价联动。
- **问题分析**
  - 768px 以下直接隐藏导航，若没有可靠移动抽屉或底部导航替代，会导致用户失去模块切换入口。
  - 这是运营平台的关键路径问题，不是单纯布局问题。
- **用户体验影响**
  - 移动端或窄屏用户无法快速进入 SOP、应用中心、更多业务场景。
  - 平板分屏、浏览器窄窗使用体验明显下降。
- **优化方案**
  1. 在当前 header 体系内补齐移动端汉堡按钮 / 底部导航，入口至少包含：首页、SOP、应用中心、亚马逊知识库、更多。
  2. 移动抽屉需支持键盘关闭、Esc 关闭、焦点回到触发按钮。
  3. 使用 `aria-expanded`、`aria-controls`、`aria-label` 表达展开状态。
  4. 移动端菜单项触控高度不低于 44px。
- **验收标准**
  - 375px 宽度下可完成所有一级模块切换。
  - 键盘 Tab 顺序进入抽屉后不丢焦点。

### P1-03 卡片整体可点击与内部按钮嵌套，交互语义不清

- **位置 / 证据**
  - `src/modules/app_center/views/overview/template.html:190-240` 等：`<article role="button" tabindex="0">` 内部包含多个 `<button>`。
- **问题分析**
  - 卡片本体承担按钮角色，内部又放置子按钮，形成嵌套交互区域。
  - 屏幕阅读器与键盘用户可能难以判断“点击卡片”和“点击子入口”的区别。
- **用户体验影响**
  - 误触率上升，尤其在移动端卡片内多个入口密集时。
  - 无障碍用户可能听到不完整或重复的交互语义。
- **优化方案**
  1. 二选一：要么整卡是单一 `<button class="app-overview-card">`，内部不再放子按钮；要么卡片保持 `<article>`，仅内部按钮可点击。
  2. 推荐方案：卡片作为信息容器，右上角/底部保留明确的“进入主应用”按钮，子入口为二级按钮。
  3. 为每个子入口增加具体 `aria-label`，例如“打开 Master Analysis 的数据采集”。
  4. 移动端将子入口改为纵向全宽按钮，减少误触。
- **验收标准**
  - 不存在可点击元素嵌套可点击元素。
  - Tab 到每个入口时，读屏标签可明确说明目标。

### P1-04 部分触控目标低于 44px

- **位置 / 证据**
  - `src/modules/app_center/app_center_style.css:735-749`：`.app-child-link` `min-height: auto`，`padding: 0.25rem 0.5rem`。
  - `src/modules/home/homeDisplay.css:302-309`：浮动快捷项为 40px。
  - `src/components/settings/systemSettings.html:177-180`：密钥可见性按钮为 28px。
- **问题分析**
  - 桌面可接受的小按钮，在触屏设备上误触率高。
  - 可访问性建议触控目标至少 44x44px。
- **用户体验影响**
  - 小屏用户点击困难，尤其是设置面板中的眼睛按钮、卡片子入口等高频操作。
- **优化方案**
  1. 全局定义 `--control-touch-min: 44px`。
  2. 交互控件默认 `min-height: 44px`；紧凑模式只能用于非触屏密度或明确桌面场景。
  3. 图标按钮视觉尺寸可保持 28-32px，但点击热区用伪元素或 padding 扩到 44px。
  4. 移动端媒体查询中强制 `.app-child-link`、设置面板图标按钮、浮动快捷项达到 44px。
- **验收标准**
  - 关键页面所有按钮、开关、图标按钮命中区域不小于 44x44px。

### P1-05 暗色模式覆盖不完整，局部硬编码会破坏主题

- **位置 / 证据**
  - `src/components/modal/AppModal.ts:64-155`：Shadow DOM 内大量 `#ffffff`、`#1e293b`、`#3b82f6`。
  - `src/components/settings/systemSettings.html`：大量 Tailwind 色阶与内联 `<style>`。
  - `src/modules/app_center/app_center_style.css:95-123`：局部覆盖 `--color-primary`。
- **问题分析**
  - Shadow DOM 模态框样式没有系统性映射全局令牌。
  - 设置面板大量渐变和色阶依赖浅色背景。
- **用户体验影响**
  - 暗色主题下可能出现高亮刺眼、文字对比不足、白色面板割裂。
  - 用户对“主题切换”的信任下降。
- **优化方案**
  1. 模态框组件暴露 `--modal-bg`、`--modal-text`、`--modal-border`、`--modal-backdrop` 等组件令牌。
  2. 设置面板抽取为 `settings-panel.css`，用语义变量替换 Tailwind 裸色阶。
  3. 禁止模块局部直接重写 `--color-primary`；改用模块专属 `--app-overview-accent` 再映射到组件令牌。
  4. 为暗色模式补充视觉回归截图：主页、应用中心、设置面板、模态框。
- **验收标准**
  - 暗色主题下正文文本对比度 ≥ 4.5:1，大字号与图标信息 ≥ 3:1。
  - 模态框与设置面板不出现纯白孤岛。

## 3. 建议优化（P2：影响体验但不阻断主流程）

### P2-01 视觉语言在“极简首页”和“彩色应用中心”之间跳变明显

- **位置 / 证据**
  - `src/modules/home/homeDisplay.css`：首页偏极简科技感、蓝青渐变。
  - `src/modules/app_center/app_center_style.css`：应用中心偏红/珊瑚局部品牌色。
- **问题分析**
  - 首页与应用中心风格不是不能不同，但目前缺少明确的品牌桥接元素。
- **用户体验影响**
  - 用户从首页进入应用中心时，可能感到像进入了另一个产品。
- **优化方案**
  1. 明确产品级“运营工作台”视觉母题：例如“冷静数据底色 + 任务高亮色”。
  2. 首页保留蓝青科技感，应用中心可保留红色强调，但统一字体、圆角、卡片阴影和标题结构。
  3. 定义模块 Accent 色表，而不是每个模块自由硬编码。

### P2-02 `!important` 使用较多，组件可组合性受损

- **位置 / 证据**
  - `src/modules/app_center/app_center_style.css` 多处 `!important`。
  - `src/modules/amz_hub/amz_hub_style.css` 多处 `!important`。
  - `src/css/components/buttons.css` 筛选按钮使用 `!important` 覆盖。
- **问题分析**
  - `!important` 往往说明选择器层级或 token 设计不合理。
- **用户体验影响**
  - 表面影响是样式难改；实际影响是未来新增状态、暗色模式、响应式覆盖会更容易失效。
- **优化方案**
  1. 建立 CSS Layer：`@layer foundation, components, modules, utilities`。
  2. 模块样式只覆盖组件令牌，不覆盖组件内部属性。
  3. 对筛选按钮、卡片、工作台容器建立标准变体类，减少模块级强制覆盖。

### P2-03 表单与设置面板视觉密度偏高

- **位置 / 证据**
  - `src/components/settings/systemSettings.html`：多段渐变卡片、图标、说明、标签、按钮堆叠。
- **问题分析**
  - 设置面板承载模型配置、网络、本地数据、性能监控，信息类型多，但视觉权重接近。
- **用户体验影响**
  - 用户难以快速识别“当前最需要操作的项”。
  - 高密度小字号在长时间配置场景下易疲劳。
- **优化方案**
  1. 将设置分为一级 Tab：模型、网络、数据、性能。
  2. 每个分区只保留一个主操作按钮，其余降级为次按钮或文本链接。
  3. 危险操作（清空数据）使用独立危险区，视觉上与普通配置隔离。
  4. 正文说明字号不低于 12px，关键输入标签保持 13-14px。

### P2-04 交互动效过度依赖 `transition: all` 与布局属性动画

- **位置 / 证据**
  - `src/css/utilities/transitions.css`：`.transition-all-fast`、`.transition-all-normal`。
  - `src/modules/home/homeDisplay.css:282-299`：浮动工作台动画 `max-width`。
  - `src/css/foundation/variables.css` 包含 bounce/elastic/spring 缓动。
- **问题分析**
  - `transition: all` 可能意外动画化尺寸、位置、阴影等昂贵属性。
  - `max-width` 动画会触发布局计算。
- **用户体验影响**
  - 低端设备或复杂页面中可能出现卡顿。
  - 动效风格不统一，按钮、卡片、面板的反馈节奏不一致。
- **优化方案**
  1. 禁用新增 `transition: all`，改为指定 `background-color, border-color, color, transform, opacity, box-shadow`。
  2. 浮动工作台展开改用 `transform + opacity`，避免 `max-width` 动画。
  3. 默认缓动使用 `--ease-smooth` 或 `--ease-out`，避免常规 UI 使用 bounce/elastic。

### P2-05 响应式布局存在横向滚动依赖

- **位置 / 证据**
  - `src/modules/app_center/app_center_style.css:561-568`：筛选行 `overflow-x: auto`。
  - `src/modules/app_center/app_center_style.css:577-579`：卡片网格 `minmax(320px, 1fr)`。
- **问题分析**
  - 横向滚动筛选在移动端可用，但发现性较弱。
  - `320px` 卡片最小宽度接近小屏宽度，叠加容器 padding 后易拥挤。
- **用户体验影响**
  - 用户可能看不到右侧筛选项。
  - 小屏卡片内容密度高，二级按钮换行后视觉拥挤。
- **优化方案**
  1. 移动端筛选改为分段控件 + “更多分类”下拉，或允许两行换行。
  2. 卡片网格使用 `minmax(min(100%, 18rem), 1fr)`。
  3. 卡片内部操作在移动端改为列表按钮，全宽排列。

### P2-06 减少动画策略存在“展开内容直接可见”的副作用

- **位置 / 证据**
  - `src/css/components/header.css:855-881`：`prefers-reduced-motion` 下 dropdown panel 被设为 `opacity: 1`、`visibility: visible`。
- **问题分析**
  - 减少动画不等于强制展开。用户选择减少动画时，隐藏状态仍应保持，只是去掉过渡。
- **用户体验影响**
  - 在减少动画模式下，下拉、通知、用户菜单可能默认暴露，造成页面噪声或遮挡。
- **优化方案**
  1. 在 `prefers-reduced-motion` 中只移除 transition/animation，不改变 visibility/opacity 的业务状态。
  2. 使用 `.is-open` 或 `[aria-expanded="true"]` 控制显示。

## 4. 可保留并强化的优点

1. **设计令牌基础扎实**：已有完整色板、字体、间距、圆角、阴影、断点定义，具备系统化升级基础。
2. **应用中心信息架构较清晰**：Hero、任务路径、分类筛选、应用矩阵的结构合理。
3. **部分无障碍实践到位**：如 `aria-live` 更新筛选数量、`aria-pressed` 表达筛选按钮状态、`focus-visible` 焦点样式。
4. **动效有减少动画意识**：已覆盖 `prefers-reduced-motion`，只是个别策略需要修正。
5. **响应式已覆盖主要断点**：应用中心有 1100/900/768/560 多级断点，后续可在此基础上细化移动体验。

## 5. 优先级实施路线

### 第一阶段：必须改进（建议先做）

1. **修复移动端导航等价入口**
   - 输出：移动抽屉 / 底部导航组件。
   - 验收：375px 可访问所有一级模块。

2. **修复卡片嵌套交互语义**
   - 输出：应用中心卡片结构调整。
   - 验收：无嵌套交互，键盘与读屏语义清晰。

3. **统一触控目标尺寸**
   - 输出：`--control-touch-min` 与按钮/图标按钮规范。
   - 验收：所有关键控件 ≥ 44x44px。

4. **收敛设计令牌与暗色模式基础**
   - 输出：令牌命名规范、组件令牌映射、暗色覆盖清单。
   - 验收：主页、应用中心、设置面板、模态框暗色主题可读。

### 第二阶段：建议优化（提升一致性与质感）

5. **整理模块 Accent 色系统**
   - 将应用中心、AMZ Hub、SOPS 等模块色彩纳入统一 Accent 表。

6. **降低设置面板视觉密度**
   - 分 Tab 或分组重构，危险操作独立专区。

7. **替换 `transition: all` 与布局属性动画**
   - 提升性能与动效一致性。

8. **改进移动端筛选与卡片布局**
   - 减少横向滚动依赖，提升发现性。

9. **减少 `!important`，建立组件变体层**
   - 提升长期可维护性。

- [ ] 为首页、应用中心、设置面板定义统一标题层级：H1 24-30px，H2 18-20px，正文 14-16px。

## 7. 推荐验收标准

1. **一致性**：同类按钮、卡片、标签、面板在 4 个核心模块中的样式差异必须来自明确变体，而不是临时覆盖。
2. **可访问性**：正常文本对比度 ≥ 4.5:1；触控目标 ≥ 44px；所有图标按钮有可读名称。
3. **响应式**：375px、768px、1024px、1440px 四档无关键功能缺失，无横向页面滚动。
4. **主题**：浅色 / 暗色模式下核心流程均可读，模态框和设置面板不出现主题割裂。
5. **交互**：键盘可完成模块导航、筛选、打开卡片入口、关闭弹层。
