# 工作台测试团队架构

## 团队组成

### 1. 测试架构师 (Test Architect)
**职责：**
- 设计整体测试策略和框架
- 定义测试标准和最佳实践
- 审查测试代码质量
- 协调各测试小组工作

### 2. Master Analysis 测试组
**成员：**
- Scraper 测试工程师
- AI Analysis 测试工程师
- Promptlab 测试工程师

**职责：**
- 测试数据采集、AI分析、提示词实验室的完整流程
- 验证数据导入导出功能
- 测试API集成和错误处理

### 3. Keyword Hunter 测试组
**成员：**
- Input 测试工程师
- Process 测试工程师
- Analysis 测试工程师

**职责：**
- 测试关键词输入、处理、分析的完整流程
- 验证关键词追踪和统计功能
- 测试数据可视化组件

### 4. 性能测试组
**职责：**
- 页面加载性能测试
- 大数据量处理性能测试
- 内存泄漏检测
- 并发操作测试

### 5. 集成测试组
**职责：**
- 跨模块流程测试
- 数据流转测试
- 路由导航测试
- 状态同步测试

## 测试策略

### 测试金字塔
```
        /\
       /  \  E2E Tests (20%)
      /____\
     /      \  Integration Tests (30%)
    /________\
   /          \  Unit Tests (50%)
  /____________\
```

### 测试覆盖目标
- 代码覆盖率: ≥ 80%
- 关键路径覆盖率: 100%
- 边界条件覆盖率: ≥ 90%

### 测试环境
- 本地开发环境: Chromium (快速反馈)
- CI/CD 环境: Chromium + Firefox + WebKit (全面覆盖)
- 移动端测试: 按需启用

## 测试数据管理

### 测试数据源
- 示例产品JSON: `examples/Amz_B01KYRUBT8_2026-02-25T07-23-54.json`
- 测试API Key: `AI2026`
- 测试ASIN列表: 维护在各测试文件中

### 数据隔离原则
- 每个测试独立准备数据
- 测试后清理临时数据
- 不依赖外部数据状态

## 测试执行流程

### 本地开发
```bash
# 快速测试（仅 Chromium）
npm run test:e2e

# 完整测试（所有浏览器）
npm run test:e2e:all

# 单个模块测试
npm run test:e2e -- scraper.spec.ts
```

### CI/CD 流程
1. 代码提交触发
2. 并行执行所有测试
3. 生成测试报告
4. 失败时保留截图和视频
5. 通知相关人员

## 质量门禁

### 代码合并要求
- ✅ 所有 E2E 测试通过
- ✅ 无控制台错误
- ✅ 性能指标达标
- ✅ 代码审查通过

### 性能基准
- 页面加载: < 3s
- 数据采集: < 30s
- AI 分析: < 30s
- 交互响应: < 200ms

## 测试报告

### 报告类型
- HTML 报告: 可视化测试结果
- JSON 报告: 自动化分析
- JUnit XML: CI/CD 集成
- 控制台输出: 实时反馈

### 报告位置
- `tests/playwright-report/` - HTML 和 JSON 报告
- `tests/screenshots/` - 失败截图
- `test-results/` - 视频录制

## 持续改进

### 测试维护
- 定期审查测试用例
- 更新测试数据
- 优化测试性能
- 修复不稳定测试

### 测试扩展
- 新功能必须包含测试
- 测试覆盖率不得降低
- 保持测试代码质量
