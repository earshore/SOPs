新人照做清单

完成标准

  • 产出新版 Title、5 条 Bullet、Search Terms。
  • 标明每个核心词对应的来源：竞品、ABA、Review 或经验判断。
  • 高危词检查结果为无 4-5 级风险词。

提交模板

Step 1: 采集竞品原始数据

工具：前台插件 / 数据采集 / 卖家精灵 (JSON/CSV)

收集 Top 20-50 的竞品 Listing 内容和最近 3 个月的 Review。不要贪多，要精。
目标： 获取竞品Listing和Review原始语料

Step 2: LLM 结构化清洗提取

工具：GPT-5-mini

上传 JSON/CSV，选择合适的分析模板策略，生成 JSON 格式的使用场景、负面痛点、积极用户原话。
目标： 将非结构化文本转化为 COSMO 可理解的"意图节点"。

Step 3: ABA 交叉验证

工具：ABA (Amazon Brand Analytics) + Excel

拿着 LLM 提取的"原生词"去 ABA 验证流量。确定主推词（高流量+高相关）和长尾词（高转化+特定场景），融合 Prompting。
目标： 确认哪些"意图"是有市场需求的，确认埋词策略。

Step 4: AI 生成文案

工具：Gemini 3 Pro

基于 A10/COSMO/Rufus 的逻辑，让 Gemini 撰写 Listing。
  • Title: 包含 ABA 核心词 + 核心场景
  • Bullets: 前 3 点针对 COSMO 场景化，后 2 点针对 Rufus 解决痛点/参数
  • Description/A+: 讲述品牌故事，增加停留时间（A10 因素）
目标： 产出Listing成品
以下为Listing编写/生成指引

标题 (Title) 编写公式

[品牌] + [核心词] + [场景/人群] + [卖点] + [规格]

✅ 正确示例

BrandX Wireless Bluetooth Headphones for Running, Active Noise Cancelling, 40H Battery, Black

❌ 错误示例

Best Headphones 2024 NEW!!! Amazing Quality Cheap Price Free Shipping

字符限制： 非媒体类按 75 字符以内准备；后台类目限制与过渡期提示必须逐 ASIN 复核
  • 同一字词（含品牌名）不得出现超过 2 次
  • 禁用 ! $ ? _ { } ^ ¬ ¦；~ # < > * 仅限编码/测量上下文
  • 禁促销用语（Best Seller、Free、Sale、Guarantee 等）与受限短语
  • 信息顺序：品牌 → 款式 → 类型 → 属性 → 颜色/尺寸 → 型号
  • 父/子变体使用一致的标题结构
  • 溢出信息放入「商品亮点」字段（约 125 字符），不放标题

五点描述 (Bullet Points)

核心原则：移动端只展示前3点的前70字符，把最硬核信息（尺寸/兼容性/材质）前置。

1 核心功能 + 强兼容性 (流量入口)
公式：[核心大词] + [适配对象/核心参数]
🇩🇪 示例： Passgenau für iPhone 15 Pro Max: Hülle aus echtem Leder...
→ 直接告诉客户给谁用，减少买错退货
2 材质工艺 + 欧标合规 (转化信任)
策略：避免虚词(Super durable)，用实词(304 Stainless Steel, OEKO-TEX Standard 100)
⚠️ 避坑：别写 Bamboo，别乱写 Antibacterial (参考受限词库)
3 使用场景 + 解决痛点 (COSMO匹配)
策略：欧洲本土化场景，捕捉长尾流量
对比： 🇺🇸 Camping → 🇩🇪 Wandern in den Alpen (阿尔卑斯徒步)
4 ⭐ 供货范围 (Box Contents) — 减少退货！
逻辑：很多退货是因为"我以为有电池，结果没有"
🇩🇪 Lieferumfang： 1x 主机, 1x Type-C线 (不含适配器)
→ 对降低欧洲站差评至关重要，预埋Rufus AI问答
5 技术参数 + 售后 (预埋Rufus AI问答)
🇩🇪 Technische Daten：尺寸、重量、电压 (220V-240V，别写美规110V)
🚫 禁写："Lifetime Warranty" / "100% Satisfaction"
✅ 可写："24-Month Support" / "Customer Service via Amazon"

A10/COSMO/Rufus 算法底层逻辑

🎯 A10 (权重核心): "客户体验优先"
  • • CTR+CR：图片/价格→点击；文案/A+→转化
  • • Sales History：断货恢复权重极慢
  • • 退货率：欧洲站高退货率=直接降权
🌐 COSMO (意图识别): "关键词→用户意图"
  • • 埋词位置：标题 + 前3点
  • • 场景化：告诉AI产品"怎么用" (如: for Gardening)
🤖 Rufus (AI问答): "生成式引擎"
  • • 数据源：后2点五点 + A+参数表 + 用户评论
  • • 防守：避免模糊描述，否则Rufus回答"不确定"
🎯 算法适配口诀：
A10抓权重
压低退货率
COSMO抓流量
前3点写场景
Rufus抓转化
后2点填参数

移动端优化 (70%+流量来源)

1
标题首屏法则
核心信息在前 70字符，否则被截断
2
主图聚焦度
竖屏模式下产品主体占比 >85%
3
前三点折叠
手机默认只显示前3点，最强卖点必须在此
4
虚拟捆绑
检查"经常一起购买"，用自家A+B产品占位
📱 手机端必查： 前70字符卖点明确？主图小屏C位？前3点抓眼球？

Search Terms 填充规范

✅ 正确做法

  • • 空格分隔关键词
  • • 不重复Title中的词
  • • 包含拼写变体/同义词
  • • 小写即可
  • • 用满250字节

❌ 禁止事项

  • • 逗号或标点分隔
  • • 竞品品牌名
  • • 主观词(best,amazing)
  • • 重复堆砌
  • • ASIN或价格

A+ 内容排版规范

核心目的：1. 消除语言障碍；2. 锁住流量（防止跳出到竞品）。采用"模块化积木"思维。

1
品牌/场景 Banner
沉浸式场景图，无文字或极少文字 → 建立第一眼好感
2
Standard 3/4 Images & Text — 核心卖点图标化
策略：Icon(图标) + 短语，用视觉语言跨越德法意西语言障碍
示例： 水滴图标 → 🇩🇪 Wasserdicht / 🇫🇷 Imperméable / 🇬🇧 Waterproof
3
Single Image & Highlights — 深度解析
左边：产品爆炸图/细节特写；右边：3-4个核心功能点
💡 这里的文字会被谷歌收录，增加Listing的SEO权重
4
⭐ Comparison Chart — 精铺卖家的"护城河" (最重要！)
逻辑：横向展示 3-5 个自家产品（类似款/升级款/配件）
目的：客户不喜欢当前款 → 点击跳到你店里的另一款，而非竞品广告。
这叫"流量闭环"，精铺模式流量利用率最高的工具！
5
Technical Specifications / FAQ — 针对德国买家
纯表格形式，列出长宽高、材质、适用标准
💡 德国人极其理性，喜欢看表格对比参数。看起来枯燥，但德国站转化率极高！
🚀 给运营团队的执行指令：
必含Comparison Chart
(流量闭环)
善用Icon图标
(跨越语言)
模块化模板
(一套套用全SKU)
图片规范：970×600px / 300dpi / 白底 / 文字占比≤20%

品牌故事 (Brand Story) 规范

📐 硬性尺寸要求 (背景图)

🖥️ 电脑端 (Desktop) 1464 x 625 px Logo放极左/极右 (中间会被挡)
📱 移动端 (Mobile) 463 x 625 px 独立设计，禁止直接缩放

🃏 卡片组合策略 (精铺版)

1
品牌起源卡 (About Brand)
虚：讲情怀/设计理念。配图：创始人/氛围图 (315x460px)。
2
四图ASIN卡 (Killer)
实：免费关联流量位！放互补爆款或新款，交叉引流。
⚠️ 美工避坑 Checklist:
  • 背景图中央区域会被挡住，严禁放文字
  • 卡片文字要少，移动端滑动快
  • 移动端背景图必须单独裁剪设计

欧洲站本地化 (Localization) 策略

🚫 拒绝机翻 (No Machine Translation)

直接翻译会导致关键词失效。必须基于当地用户用语习惯埋词。

  • • 英文：Mobile Phone Case
  • • 德文直译：Mobiltelefon-Fall (错误)
  • • 德文地道：Handyhülle (正确流量词)

🌍 统一运营 (Pan-EU Listing)

  • • ASIN共享：使用相同ASIN在5国上架，共享评论(Review)
  • • 图片文案：主图/A+尽量使用图标或英语通用词，减少翻译工作量
  • • 小语种：雇佣本地人或使用高级AI(ChatGPT-5)进行润色
关键词是否被正确收录

先查收录，再看排名，最后看转化

参考行业实操经验提炼：判断一个词有没有被亚马逊正确收录，核心不是“感觉有埋词”，而是要把“已收录”和“有自然位次”分开验证。

快速判断公式
收录
搜 ASIN + 关键词
排名
搜纯关键词看位次
转化
看点击后是否成交

标准检查流程

1
修改后先等待同步：新埋词或新文案上线后，建议预留 24-72 小时 再做收录判断。
2
按词逐个测试：优先测主词、核心长尾词，不要一上来测试过长组合词，避免误判。
3
前台搜 ASIN + 空格 + 关键词：能搜到该 ASIN，说明这个词大概率已被系统收录。
4
再搜纯关键词：看 ASIN 是否有自然位置。有收录但没排名，通常是权重不够，不等于没收录。
OR
看ASIN权威链接：在listing页面按 CTRL+U 打开网页代码页，按 CTRL+F 打开搜索框，搜索canonical（后面的链接就是产品的权威链接），在权威来链接里可以看亚马逊是否有收录自己的关键词。

实操判断口径

✅ 已被收录
搜索 ASIN + 关键词 能检索到当前产品。
📍 有自然排名
单搜关键词时，ASIN 在自然结果里有位置，说明该词不仅收录，还开始拿到曝光。
⚠️ 常见误判
“纯关键词搜不到”不一定是没收录，也可能只是该词竞争大、相关性弱、历史销量权重不足。
运营执行口诀
先证明确实被收录
不要只看文案里有没有写
再判断有没有自然位次
收录 ≠ 排名
最后结合点击与转化
排名 ≠ 出单

搜不到时优先排查

  • 关键词是否只埋在低权重位置，标题/前 3 点完全没覆盖。
  • Search Terms 是否被重复词、无关词、品牌词占满，浪费了可收录空间。
  • 词本身是否类目相关性不足，或者表达不符合当地买家真实搜索习惯。
  • 刚改完文案就立刻测试，系统索引尚未刷新。
  • 父子体 / 站点 / 类目切换错误，导致检查口径不一致。

建议检查节奏

上新 / 大改文案后，第 2 天先做第一轮收录检查。
主词先查，随后补查场景词、功能词、长尾词。
若已收录但没位次，优先从 CTR、转化率、评论质量与价格竞争力补权重。
检查结论写法建议： 把结果拆成“是否收录 / 自然排名区间 / 下一步动作”三列记录，团队复盘时最清晰。
