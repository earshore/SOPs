# 网页加载问题修复报告

## 问题总结

执行 `npm run dev` 后，网页出现 **Maximum call stack size exceeded（堆栈溢出）** 错误，导致 Alpine.js、Zustand Store 和 Router 无法正常加载。

---

## 根本原因

### 问题 1：LoggerService 中的无限递归调用

**位置：** `src/services/loggerService.ts` 的 `_consoleLog` 方法

**问题代码：**
```typescript
private _consoleLog(entry: LogEntry): void {
  // ...
  switch (level) {
    case LOG_LEVELS.DEBUG:
      Logger.debug(fullMessage, logData);  // ❌ 调用自身！
      break;
    case LOG_LEVELS.ERROR:
      Logger.error(fullMessage, logData);  // ❌ 调用自身！
      break;
  }
}
```

**调用链：**
```
Logger.error() 
  → _log() 
  → _consoleLog() 
  → Logger.error()  // 回到起点，形成无限循环！
  → ...
```

### 问题 2：跨平台兼容性问题

**位置：** `package.json` 的 `dev` 脚本

**问题代码：**
```json
"dev": "vite & sleep 2 && open -na 'Google Chrome' --args --incognito http://localhost:5173"
```

- `open -na 'Google Chrome'` 是 macOS 专用命令
- `sleep` 在 Windows PowerShell/CMD 中不可用
- 在 Windows 系统上无法正常运行

---

## 修复方案

### 修复 1：LoggerService 无限递归

**修改文件：** `src/services/loggerService.ts`

**修复后代码：**
```typescript
private _consoleLog(entry: LogEntry): void {
  const { level, levelName, message, data, module, timestamp } = entry;
  const time = new Date(timestamp).toLocaleTimeString('zh-CN');
  const color = LEVEL_COLORS[level as LogLevelValue] || '#6B7280';

  const prefix = `%c[${time}] [${levelName.toUpperCase()}] [${module}]`;
  const style = `color: ${color}; font-weight: bold;`;

  // ✅ 修复：直接使用原生 console 方法，避免递归调用
  const fullMessage = `${prefix} ${message}`;
  
  switch (level) {
    case LOG_LEVELS.DEBUG:
      console.debug(fullMessage, style, data);  // ✅ 使用原生 console
      break;
    case LOG_LEVELS.INFO:
      console.info(fullMessage, style, data);
      break;
    case LOG_LEVELS.WARN:
      console.warn(fullMessage, style, data);
      break;
    case LOG_LEVELS.ERROR:
    case LOG_LEVELS.FATAL:
      console.error(fullMessage, style, data);  // ✅ 使用原生 console
      break;
  }
}
```

### 修复 2：ErrorTracker 日志输出

**修改文件：** `src/services/errorTracker.ts`

**修复后代码：**
```typescript
private logError(error: ErrorRecord): void {
  // ✅ 修复：避免循环调用 - 直接使用console而不是Logger
  const logLevel = error.severity === ErrorSeverity.CRITICAL || error.severity === ErrorSeverity.HIGH
    ? 'error'
    : 'warn';

  const logData = {
    id: error.id,
    severity: error.severity,
    count: error.count,
    stack: error.stack,
    context: error.context
  };

  // 直接使用console，避免通过Logger触发新的错误
  console[logLevel](`[ErrorTracker] [${error.type}] ${error.message}`, logData);
}
```

### 修复 3：GlobalErrorHandler 循环检测

**修改文件：** `src/common/errors/GlobalErrorHandler.ts`

**添加的保护机制：**
```typescript
export class GlobalErrorHandler {
  private isHandlingError: boolean = false; // 防止循环调用标志

  handle(error: Error | AppError, options: ErrorHandlerOptions = {}): void {
    // 防止循环调用
    if (this.isHandlingError) {
      console.error('[GlobalErrorHandler] Recursive error detected, skipping:', error.message);
      return;
    }

    try {
      this.isHandlingError = true;
      // ... 错误处理逻辑
    } catch (innerError) {
      console.error('[GlobalErrorHandler] Error in error handler:', innerError);
    } finally {
      this.isHandlingError = false;
    }
  }
}
```

### 修复 4：AppError 构造函数保护

**修改文件：** `src/common/errors/AppError.ts`

**添加的保护机制：**
```typescript
constructor(...) {
  // ...
  
  // 捕获堆栈跟踪时避免循环
  try {
    if (Error.captureStackTrace) {
      Error.captureStackTrace(this, this.constructor);
    }
  } catch (e) {
    console.warn('[AppError] Failed to capture stack trace:', e);
  }
}
```

## 经验教训

### 1. 避免在日志系统中使用日志系统

日志记录函数（如 `_consoleLog`）不应该调用自身的日志方法，应该直接使用原生 `console` API。

### 2. 错误处理需要循环检测

在全局错误处理器中，必须添加循环检测机制，防止错误处理本身触发新的错误。

### 3. 跨平台脚本需要兼容性测试

开发脚本应该在所有目标平台上测试，避免使用平台特定的命令。

### 4. 主动验证和完整日志分析

- 不能仅依赖表面现象判断问题
- 需要查看完整的控制台输出
- 使用自动化工具捕获和分析错误
