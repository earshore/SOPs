# 内容设计规范（Content Design）

**Status:** active · SSOT · v1.0  
**Updated:** 2026-07-26  
**Owner:** 产品规划 + 前端  
**适用范围:** 全部用户可见中文文案（UI、Toast、空状态、错误、确认框、设置、文档面向用户的句子）

> **上位法：** [PRODUCT_PRINCIPLES](./PRODUCT_PRINCIPLES.md)（P7 去 AI 味）  
> **交叉：** [COMPONENT_GUIDELINES](./COMPONENT_GUIDELINES.md)、[MODAL](./MODAL_DEVELOPMENT_GUIDELINES.md)、[DEGRADATION_MATRIX](./troubleshooting/DEGRADATION_MATRIX.md)

---

## 1. 目标

1. 用户 **3 秒内**看懂要做什么、发生了什么。  
2. 不写「正确的废话」和说明书腔。  
3. 错误可操作；危险说后果。  
4. 全站语气一致（工具、不是营销号、不是客服机器人）。

---

## 2. 语气与人称

| 维度 | 采用 | 避免 |
| --- | --- | --- |
| 人称 | 直接祈使 / 名词短语（「保存配置」「缺 API Key」） | 「您可以尝试…」「我们建议您…」堆砌 |
| 态度 | 冷静、专业、简短 | 卖萌、恐吓、过度道歉 |
| 技术词 | 用户已见的产品词可保留（Endpoint、Key、ASIN） | 无必要的实现细节（「normalize」「payload」「SSOT」） |
| 英文 | 专有名词、模型 id、档位 low/max 可保留 | 中英混杂正确废话（「进行 configure 操作」） |

**默认语言：** 简体中文 UI。暂无 i18n 合同；新增英文 UI 须产品书面批准。

---

## 3. 去 AI 味规则（强制）

### 3.1 禁止模式

| 模式 | 反例 | 改法 |
| --- | --- | --- |
| 正确的废话 | 「按应用分组的默认模型与运行参数」 | 删；标题已够 |
| 与标题同义 | 区标题「数据与备份」+ desc「导出、导入与清理」 | 删 desc 或只补**增量**信息 |
| 说明书长段 | 「仅当上游 API 文档明确支持…多数场景…」 | 「多数保持不发送」 |
| 向导口吻 | 「配置看起来可用。建议先测试连接…」 | 「可测试连接」 |
| 营销腔 | 「更稳定的 IP 池和验证码自动绕过」 | 「适合大批量采集」或删 |
| 重复边界 | 三处写「密钥仅存本机」 | 一处诚实边界即可 |
| Badge 堆叠 | 同区 3+ 徽章说同一件事 | 每区主 badge ≤ 1–2 |

### 3.2 允许保留的「长」

| 类型 | 原因 |
| --- | --- |
| 安全边界句 | 本机密钥、非服务端托管、扩展风险（可短，不可假） |
| 破坏操作后果 | 删什么、是否可恢复 |
| 导入/导出确认 | 含密钥风险提示 |
| 降级/错误可操作提示 | 指向设置或重试 |

## 4. 文案类型配方

### 4.1 页面 / 区标题

- 名词或动宾短短语：`工具策略`、`数据导入与导出`  
- 不用完整句：`在这里您可以配置…`

### 4.2 区描述 / card desc

- **有增量才写**；否则空着。  
- 上限：一行，约 20 字内优先。  
- 好：`超时、重试与一键预设`  
- 坏：`管理请求超时、并发、重试、批次和缓存策略`（与字段重复）

### 4.3 按钮

| 类型 | 用词 |
| --- | --- |
| 主保存 | `保存配置` / `保存工具与运行策略`（与动作一致） |
| 次要 | `测试连接`、`导出`、`导入备份`、`恢复默认` |
| 危险 | `清空全部本地数据`（说清对象） |
| 禁止 | `确定`（无上下文）、`提交`（除非表单语义清晰）、`点击这里` |

同一操作区 **主按钮文案唯一**；不要两个「保存」语义不同却同名。

### 4.4 开关 / 分段

- 标签是**状态名**或**能力名**：`启用业务工具`、`推理等级`  
- 即时保存的控件：成功 Toast 可用短句：`推理等级已保存`（不必「已成功为您保存…」）

### 4.5 Toast

| 场景 | 模式 | 例 |
| --- | --- | --- |
| 成功 | 结果名词 + 已保存/已完成 | `LLM 配置已保存` |
| 警告 | 缺什么 / 先做什么 | `请填写 API Key` |
| 失败 | 现象 + 可选下一步 | `连接失败`；详情进日志或设置 |
| 禁止 | 长教程、emoji 堆、假友好 | — |

时长：默认短；连续即时保存避免刷屏（可合并文案，勿每键一 toast）。

### 4.6 空状态

结构固定：

1. **标题**（发生了什么）：`暂无分析报告`  
2. **一句说明**（为何/可做什么）：`选择维度后开始分析`  
3. **可选 CTA**

使用共享 `.empty-state`（见组件规范）。

### 4.7 错误与降级

- 用户句优先走统一 LLM 失败 UX（`formatLlmFailureUx` / 错误码表）。  
- 需要行动时给 **一个**主行动：`打开设置`。  
- 技术码可进详情/日志，不塞满 Toast。  
- 对照：[LLM_ERROR_CODES](./troubleshooting/LLM_ERROR_CODES.md)、[DEGRADATION_MATRIX](./troubleshooting/DEGRADATION_MATRIX.md)。

### 4.8 危险确认

- 标题：动作 + 对象。  
- 正文：不可逆？删哪些？是否建议先导出？  
- 确认按钮：用危险动词，不用中性「确定」。  
- 实现：`confirmWithModal`（Modal 规范）。

## 5. 设置区专项

| 规则 | 说明 |
| --- | --- |
| 即时保存 vs 显式保存 | 按钮/开关偏好可即时保存；长表单点保存；**保存后不关面板** |
| 就绪状态 | 用状态短句：`缺 Endpoint` / `缺 API Key` / `未选模型` / `可测试连接` |
| 帮助 tip | 与标题重复则删；只放后果或例外 |
| 二级导航标签 | 与内容区标题一致，便于扫读 |

系统设置文案曾系统收敛（rc.8）；新增设置句须过 §3 检查表。

## 6. 审查清单（文案 PR）

- [ ] 删与标题同义的 desc  
- [ ] 无「建议您 / 看起来 / 进行…操作」腔  
- [ ] 按钮动词与结果一致  
- [ ] 危险说后果  
- [ ] 错误可操作  
- [ ] Badge 未刷屏  
- [ ] 安全边界未假承诺「云端加密托管」

## 7. 反例 → 正例速查

| 反例 | 正例 |
| --- | --- |
| 配置看起来可用。建议先测试连接，确认后再保存。 | 可测试连接 |
| 将保存当前面板中的全部运行时策略（含…） | 含采集运行策略。恢复默认：仅表单，需再保存。 |
| 按分类选择导出内容 | （删） |
| 修改后立即影响当前运行时 | （删；用「即时生效」badge 即可） |
| 官方 API 或兼容网关（装饰 badge） | （删或留一处正文） |
